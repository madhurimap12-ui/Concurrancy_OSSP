What happens when many students click at once?

Students→TCP accept()→Bounded queue→Worker pool→Resource/cache→HTTP response

The key idea is concurrency: requests can be accepted and processed by multiple POSIX worker threads instead of waiting for one request to finish before starting the next.

Why is there a server button?

Students need a portal entry point, not server-control privileges. This button opens the resource portal on port 9090. Start/stop, fault injection, worker configuration and benchmarks remain administrator actions.

Concurrency · Worker Pool

Producer/consumer behavior with a bounded queue, mutex and condition variable.

Performance Laboratory

Benchmark = a controlled, repeatable workload used to measure how concurrency configuration changes throughput.

Keep the request count the same when comparing worker configurations.

What does the benchmark prove?

  • It creates concurrent HTTP requests to /health.
  • It measures elapsed time, successful requests and requests/sec.
  • Repeat the same workload with 1, 2, 4 and 8 workers.
  • Observe queue, CPU, memory, active connections and errors alongside throughput.
  • Results are measured on the machine running the project; they are not fixed claims.
